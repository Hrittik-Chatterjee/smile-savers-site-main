# External reference material — not executed, not imported

Archived here for provenance, not as runtime code. Nothing in this project's
`package.json` scripts, `lib/`, or other `scripts/` files imports, requires,
or executes anything under this directory. If that ever changes, it should
change deliberately and be visible in a diff — not by accident because a file
happened to sit inside `design-intelligence/`.

## ai-design-execution-knowledge-pack-v1.1.0/

An uploaded third-party ZIP (`AIDesignExecutionKnowledgePackv1.1.0.zip`),
independently verified before being archived here:

- All 19 files' SHA-256 hashes recomputed and matched against its own
  `manifests/pack-manifest.json` — confirmed honest, not just decorative.
- Both scripts (`scripts/record-hook.mjs`, `scripts/verify-cache.mjs`) read in
  full — no shell execution, no network calls, no destructive filesystem
  operations. Safe to archive.
- **One integrity caveat found by running Prettier over it**: the pack's own
  `knowledge/policies/cache-policy.json` is not valid JSON (its `rules` array
  is never closed before the final `}`; `python3 -c "import json; json.load(...)"`
  confirms the parse error at the same position Prettier reported). The
  pack's claimed "ZIP integrity test: PASS" checked byte/CRC integrity only —
  that a file's bytes weren't corrupted in transit — which is a different
  property from the file's *content* being well-formed. Left untouched here
  (a byte-identical `diff` against the freshly-extracted original confirms
  Prettier correctly errored rather than silently rewrote it), since this
  archive exists to preserve exactly what was uploaded, not a corrected
  version of it. Every other file in the pack parses/reads cleanly.

### What this means going forward

- `execution-intelligence/record-event.mjs` and `lib/cache.mjs` /
  `scripts/cache-report.mjs` remain the single canonical implementations.
  Nothing here supersedes or duplicates them at runtime.
- The pack's own `pack-manifest.json` hashes were independently reproduced,
  not merely trusted — see the git history for the exact verification
  commands used.
